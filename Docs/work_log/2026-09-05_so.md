## 1. Done / やったこと

- **`config-parser.md`** — `commit dcfb3b5`. Written contract-first, as `Maze` was. It opens with a plain-language
  section on what a configuration file is *for*, because the module only makes sense once you see that
  **`config.txt` is the program's only input** and that three of §IV.2's four error examples are this module.
  Thirty-one edge cases, each one a future test.
- **Five decisions settled.** D1 = a frozen `Config` dataclass, so a misspelled field fails at lint time and no
  later stage can rewrite what the user asked for. D2 = the parser checks everything answerable from the file
  alone, with the dividing line stated once: **if the question needs the maze, it is W11's**. D5 = `True` /
  `False` only, matching §IV.3 exactly.
- **Corrected `01_kickoff.md` 3.2**, which still said the config's `(x, y)` is converted at parse time. That
  predates wrapping the grid in a class: `Maze` speaks `(x, y)` too and hides the transposition, so **there is one
  coordinate order in the whole program and no boundary conversion**. Following the old wording would have
  transposed every coordinate, visible only on non-square mazes.
- **`_read_pairs`** — `commit 33feea4`. The syntax layer: strip, drop blank and comment lines, split on the first
  `=`. Each value is stored **with the line it came from**, because the stages that interpret values report their
  errors long after the text is gone and §IV.2 wants a line the user can open.
- **Fourteen tests** — `commit f1df082`. Comparing the **whole dictionary** rather than one key is what makes them
  work; see §3.
- **`_where`, `_as_filename`, `_as_bool`, `_as_int`** — working tree. One converter per **type**, not one branch
  per key: `WIDTH`/`HEIGHT` share a conversion and so do `ENTRY`/`EXIT`, so six keys need four functions and each
  rule is written once.
- **`_as_int` takes `minimum` with no default.** Every caller states its own range — 1 for sizes, 0 for the parts
  of a coordinate, `None` for a seed. A default would have allowed *forgetting* the bound, and a forgotten bound
  accepts `WIDTH=0` in silence.

## 2. Next / 次にやること

1. **Two test fixes** before anything else: `assert result == True` is `E712`, and
   `test_as_bool_rejects_other_spellings` puts four calls inside one `pytest.raises` block, so only the first one
   runs. Right now nothing stops `"1"` or `"yes"` from being accepted.
2. **Tests for `_as_int`** — five of them. Two matter: `minimum=0` must still check the bound (an implementation
   written with `if minimum:` passes every other test), and `minimum=None` must accept a negative number.
3. **`_as_coord`** — split on `,`, require exactly two parts, convert each with `_as_int(minimum=0)`. It is the
   only converter that reuses another one, which is the payoff of splitting by type.
4. **Step 4** — the mandatory keys, and the checks that need two keys at once (entry inside the grid, entry ≠
   exit). Until this exists, `parse_config` can still raise `KeyError`.
5. **`load_config` and the default `config.txt`.** The file at the repo root is **empty** while §IV.3 requires a
   default config and `make run` already points at it.
