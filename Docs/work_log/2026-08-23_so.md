## 1. Done / やったこと

Steps 1–3 of `Docs/implementation_plans/maze-data-structure.md` §3, each with tests.

- **`Direction`** — an `IntEnum` whose values *are* the §IV.5 bits, plus `opposite` and `delta`
  as properties backed by module-level lookup tables — `commit c097033`, tests `15c5489`.
  A dict cannot live in an `Enum` class body, so both tables sit after the class.
- **`Maze.__init__`** — allocates the grid with every wall closed, refuses a size below 1, and
  keeps `width`, `height` and `reserved` behind read-only properties — `commit cb42eb3`.
  `_ALL_WALLS` is derived from the four `Direction` values rather than written as `15`.
- **Exceptions** — `MazeError` with `OutOfBoundsError` and `NotAdjacentError` under it, so the
  top-level handler can tell a bad coordinate from a bug in our own code (decision 3.9).
- **Read accessors** — `contains`, `is_reserved`, `walls_at`, `is_open` — `commit 28f2e76`,
  tests `3959e75`. `walls_at` guards through `contains`, and `is_open` goes through `walls_at`,
  so the bounds check exists in exactly one place.
- **A design decision recorded in its docstring**: `is_reserved` answers `False` outside the grid
  instead of raising. Unlike `walls_at`, a set lookup cannot return the wrong cell, so there is
  nothing to guard against. The asymmetry between the two is deliberate.
- **Docstrings are written in English.** This is what makes decision 7.3 work at all — javi has to
  be able to read them, and with no Pull Requests they are the only place the reasoning lives.
- Created a branch for code work; documentation keeps going straight to `main` (decision 1.2).
